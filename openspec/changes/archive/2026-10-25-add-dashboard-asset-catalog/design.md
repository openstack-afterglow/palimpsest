## Architecture

`api/catalog.py` validates bounded query/pagination and explicit DTOs in `catalog_dto.py`; `services/catalog.py` makes only SELECTs against existing Hub layer/access/build/image-export tables. Consumer authority is the unchanged `_legacy_inventory` dependency (fresh original-caller native package inventory policy), with independent `packages:read` represented by `download_allowed`. Operator routes use `require_global_admin`, sharing fresh `_package_admin_context` human/native-system validation with `require_admin` but allowing truly global reads without a fabricated target. Original subject, enabled home domain, native system role graph, service/delegation vetoes and independent `system:manage` policy are mandatory. A present original project retains enabled checks. Targetless policy has no made-up project credential/target and evaluates only system management. Existing target-bound require_token/require_admin and private package rules are unchanged.

## Graph and disclosure

Local runtime eligibility is explicit, separate from complete reusable ancestry: `local_supported` requires a visible raw/qcow2 cloud-image base and every base/layer architecture known and matching x86_64 or aarch64. `local_reason` is null when eligible, otherwise base-image-required, base-image-format-unsupported, architecture-unknown or architecture-mismatch. No-base complete chains stay discoverable but do not receive runnable commands. Host-specific backend prerequisites, CAS validation and guest readiness are not established by this metadata flag. Asset size_bytes sums complete chain plus the visible included base, excluding tar/config/index metadata rather than claiming actual archive length.

Asset pagination is over the ordered SQL **candidate leaves**, not the post-validation complete-result set. A request fetches at most `limit+1` rows at the supplied SQL offset and verifies only the first `limit`. Missing/private/incomplete chains are dropped within that page without rescanning earlier candidates or filling from subsequent pages. `has_more` comes from SQL lookahead and `next_offset=offset+candidate_rows_examined` when more exist; returned items may be fewer than limit or empty with a valid next offset. Clients must follow next_offset, not infer end-of-results from items.length. Admin LayerPage retains ordinary row pagination. Global admin visibility is absolute public/site/shared/private, never relative to the original session project. All catalog graph walks reuse native runtime graph `MAX_DEPTH=64` (parent edges); exceeding it fails the entire request explicitly with413, rather than silently claiming incomplete totals.

Consumer leaf selection excludes parents of visible children only. A hidden child cannot suppress its visible parent or leak a private-child count. Search applies after leaf selection. Each candidate must have a complete visible acyclic parent chain of actual SquashFS descriptors, plus a visible cloud-image base when one is declared; missing/hidden/invalid dependencies are omitted, never disclosed. Assets contain only the agreed bundle DTO; no project/user IDs, child list, config or origin jobs. An absent declared base stays null, not a fabricated runtime guarantee. Structural completeness is not proof of CAS availability or boot compatibility: existing bundle export validates actual payloads and selected include-base requirements.

Admin detail follows true `parent_digest` root-to-parent edges, excluding selected self even in cycles. `chain_complete` is false for missing/cyclic ancestry or a declared invalid/missing base. Children are direct-only, deterministic, capped at50 with `children_has_more`. Detail may expose global ownership only under the new operator endpoint. Hub has no durable profile records, so `bundles=[]`.

## Provenance

A completed `PalimpsestHubBuild.output_digest` link is recorded Hub build evidence. A completed `PalimpsestImageExport.result_blob_digest` link is recorded Glance export evidence (including legitimate result reuse); neither claims to identify the first-ever creation of bytes. The projection never reads recipes, job errors, paths or caller config for attestation. Upload and bundle-import sessions are deleted and native registration has no durable origin receipt, so unlinked rows remain `unknown/unknown/unrecorded`. The shared DTO's `registered/upload-or-import` variant is reserved for durable registration evidence, not guessed from an old row's mere existence. No digest/config changes or new provenance schema are introduced.

## Search compatibility

`q` is at most128 characters. SQL LOWER plus escaped LIKE treats `%`, `_` and backslash literally; name or matching tag selects packages within the existing project/type/key scope. The cursor binds normalized search as well as the pre-existing actor/type context. Absent or empty search preserves the exact old binding. Changing a nonempty query rejects the cursor rather than leaking or skipping another search.

## Evidence boundary

The isolated fixture creates SQLite tables/rows only inside caller-owned temporary storage, mounts the actual native catalog router (package router only when requested by tests) without main lifespan, and replaces external identity boundaries. Actual `require_global_admin`, service queries and response validation execute. Existing `test_auth.py::native_http` additionally defines real loopback Keystone+Hub HTTP tests of project/system/unscoped global admin, revocation, disabled identity/home-domain and service/delegation vetoes. The catalog runner is test-only and must never be deployed. All checks and source-marker stamping are deferred to the parent; no test-passed/live-qualified claims are made.

Parent transport fixture follow-through: the reusable fixture now seeds real private CAS bytes plus actual native oslo.policy evaluation from a temporary policy-only namespace, and includes only safe existing layer read/blob/bundle-export routes alongside catalog. Production settings/lifespan remain unused; external identity/context boundaries alone are synthetic. Public base0→torch-root1→torch-leaf2 and foreign-private rows exercise native SQL/CAS HTTP without implying genuine filesystem/runtime qualification. Global native token validation occurs once per request; actual human context rereads native user/domain/system authority rather than a redundant immediate token lookup.
