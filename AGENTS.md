# Palimpsest Local contributor rules

Details: [contributor workflow](openspec/specs/contributor-workflow/spec.md) and [CI safety/performance](openspec/specs/ci-safety-and-performance/spec.md). Read both; this entry does not relax either spec.

1. Resume: read README Development, the latest [handoff](docs/development-handoff.md) checkpoint, [ARCHITECTURE.md](ARCHITECTURE.md) and both specs; compare source, `git status --short`, staged/unstaged diffs and recent commits. Preserve others' staged work, evidence and approvals. Astra plans/orchestrates, Sol develops, with independent review; report unavailable roles rather than silently substituting.
2. Review source and affected docs before code/config/schema/deploy/test edits. Update contracts and maintenance summary together; stamp only after source review and run applicable working/staged architecture guard before completion. Plans are not proof; never copy secrets. Distinguish test-defined, test-passed and live-verified.
3. Start at affected nodes/lanes; native, ML, GPU and privileged proofs require separate prerequisites and authorization. Portable success is not native success. Update the handoff with real SHA, checks, failures and pending approvals; never backfill old results.
4. CI changes retain hosted-only PR execution and strict hosted required checks; native only on trusted dev/main pushes or approved v* tags behind protected environment approval, quota-limited Nova ownership and exact cleanup. Keep runner21 offline, least-privilege tokens, repo-wide serialization and fail-closed evidence/verdicts. Measure before/after; preserve publication exceptions and shard gaps pending owner decision. Docs/manual proof do not authorize remote CI, secrets, publication, helper transfer, device reassignment or retained VM deletion.
